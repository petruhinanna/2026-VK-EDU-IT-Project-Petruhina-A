## 1. C4, уровень 1 — Контекст

C4 Context показывает систему целиком: кто взаимодействует с IT QUEST и какие внешние сервисы нужны для работы MVP.

На этом уровне не показывается внутренняя техническая реализация. Видно только саму систему, пользователей и внешние интеграции.

### Основные участники

| Участник | Что делает |
|---|---|
| **Учащийся 9–11 класса** | Выбирает IT-направление, записывается на профпробу, проходит очное или дистанционное занятие и смотрит результат. |
| **Родитель** | Смотрит информацию о профпробе, помогает принять решение об участии, оплачивает занятие и может посмотреть результат вместе с ребёнком. |
| **Наставник** | Проводит профпробу, объясняет практическое задание, помогает участникам и вносит результат после занятия. |
| **Администратор** | Управляет каталогом профпроб, расписанием, пользователями, стоимостью занятий и контентом платформы. |

### Внешние системы

| Внешняя система | Для чего нужна |
|---|---|
| **Платёжный сервис** | Обрабатывает разовую оплату выбранной профпробы и возвращает статус платежа. |
| **Почтовый сервис** | Отправляет подтверждения записи, уведомления об оплате и сообщения о готовности результата. |
| **Сервис push-уведомлений** | Отправляет быстрые уведомления о записи, оплате, напоминаниях и результате. |
| **Сервис видеосвязи** | Используется для дистанционных профпроб, если участник не может прийти очно. |

## 4. Стек технологий и обоснование

| Слой | Технология | Обоснование |
|---|---|---|
| **Frontend** | React | Используется для пользовательского интерфейса: каталога профпроб, карточки занятия, записи, оплаты, личного профиля, кабинета наставника и админ-панели. React выбран потому, что позволяет быстро собрать адаптивную веб-платформу для компьютеров и телефонов. |
| **Backend** | Node.js + Express.js | Отвечает за основную бизнес-логику: регистрацию, каталог профпроб, запись на занятие, оплату, результаты и разграничение доступа по ролям. Связка Node.js + Express.js выбрана как простое и популярное решение для быстрого создания API в MVP. |
| **Основная база данных** | PostgreSQL | Хранит пользователей, роли, профпробы, расписание, свободные места, записи, платежи и результаты. PostgreSQL подходит проекту, потому что в системе много связанных данных: пользователь связан с записью, запись — с профпробой, а результат — с конкретным участником. |
| **Кэш и временные данные** | Redis | Используется для временного удержания места на профпробе во время оплаты, кэширования популярных профпроб и очередей уведомлений. Redis выбран потому, что быстро работает с временными данными и снижает нагрузку на основную базу. |
| **Reverse proxy** | NGINX | Принимает внешние запросы, отдаёт frontend и перенаправляет API-запросы на backend. NGINX выбран как стандартная точка входа в веб-приложение: он помогает настроить HTTPS, маршрутизацию и отдачу статических файлов. |
| **Хранилище файлов** | S3-совместимое хранилище | Хранит материалы профпроб: задания, изображения, шаблоны интерфейсов, документы и вложения. Такое хранилище выбрано, потому что файлы удобнее хранить отдельно от PostgreSQL, не перегружая основную базу данных. |
| **Платежи** | ЮKassa API | Обрабатывает разовую оплату очных и дистанционных профпроб. ЮKassa API выбран, потому что подходит для российского B2C-проекта и позволяет не хранить банковские данные пользователей внутри IT QUEST. |
| **Email-уведомления** | Почтовый сервис | Отправляет подтверждение записи, уведомление об успешной оплате, напоминание о занятии и сообщение о готовности результата. Email выбран как простой и надёжный канал уведомлений для MVP. |
| **Push-уведомления** | Firebase Cloud Messaging | Отправляет быстрые напоминания о профпробе и уведомления о готовности результата. Firebase Cloud Messaging выбран, потому что push-уведомления помогают снизить риск неявки участника и быстрее донести важную информацию. |
| **Дистанционные занятия** | Яндекс Телемост | Используется для проведения дистанционных профпроб. Ссылка на онлайн-встречу хранится в системе и показывается участнику после успешной записи и оплаты. Готовый сервис выбран потому, что для MVP нет смысла создавать собственную видеоплатформу. |
| **Мониторинг** | Prometheus + Grafana | Отслеживают нагрузку, ошибки, доступность backend, состояние базы данных и другие метрики. Эти инструменты выбраны, чтобы команда могла быстро заметить проблемы с оплатой, записью или API после запуска MVP. |
| **Хостинг** | Yandex Cloud | Используется для размещения приложения, базы данных, Redis и файлового хранилища. Yandex Cloud выбран потому, что позволяет быстро развернуть MVP без покупки и настройки физических серверов. |
