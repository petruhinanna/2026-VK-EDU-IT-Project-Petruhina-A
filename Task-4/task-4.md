## 1. C4, уровень 1 — Контекст

C4 Context показывает систему целиком: кто взаимодействует с IT QUEST и какие внешние сервисы нужны для работы MVP.

На этом уровне не показывается внутренняя техническая реализация. Видно только саму систему, пользователей и внешние интеграции.

### Основные участники

| Участник | Что делает |
|---|---|
| **Учащийся 9–11 класса** | Выбирает IT-направление, записывается на профпробу, проходит очное или дистанционное занятие и смотрит результат. |
| **Родитель** | Смотрит информацию о профпробе, помогает принять решение об участии, оплачивает занятие и может посмотреть результат вместе с ребёнком. |
| **Наставник** | Проводит профпробу, объясняет практическое задание, помогает участникам и вносит результат после занятия. |
| **Администратор** | Управляет каталогом профпроб, расписанием, пользователями, стоимостью занятий и контентом платформы. |

### Внешние системы

| Внешняя система | Для чего нужна |
|---|---|
| **Платёжный сервис** | Обрабатывает разовую оплату выбранной профпробы и возвращает статус платежа. |
| **Почтовый сервис** | Отправляет подтверждения записи, уведомления об оплате и сообщения о готовности результата. |
| **Сервис push-уведомлений** | Отправляет быстрые уведомления о записи, оплате, напоминаниях и результате. |
| **Сервис видеосвязи** | Используется для дистанционных профпроб, если участник не может прийти очно. |

## 4. Стек технологий и обоснование

| Слой | Технология | Обоснование |
|---|---|---|
| **Веб-клиент для учащихся и родителей** | React + TypeScript | Для MVP достаточно адаптивного веб-приложения, которое открывается и с компьютера, и с телефона. Учащийся сможет выбрать профпробу, записаться, оплатить занятие и посмотреть результат. TypeScript снижает количество ошибок при работе с данными профпроб, записей и оплат. |
| **Кабинет наставника** | React + TypeScript | Наставнику нужен простой интерфейс: посмотреть список записавшихся участников, выбрать участника и внести результат после занятия. Это можно быстро реализовать на том же frontend-стеке. |
| **Админ-панель** | React Admin / React + TypeScript | Администратору нужно создавать профпробы, редактировать расписание, указывать цену занятия, управлять слотами и смотреть записи. React Admin ускоряет разработку CRUD-интерфейсов для MVP. |
| **Reverse proxy** | Nginx | Единая точка входа в систему: HTTPS, маршрутизация запросов на frontend и backend, отдача статики, базовое кеширование. Помогает проще развернуть приложение на сервере. |
| **Backend API** | Node.js + NestJS | Backend отвечает за регистрацию, роли, каталог профпроб, запись на слот, оплату, результаты и права доступа. NestJS удобно делит проект на модули: Users, Trials, Bookings, Payments, Results, Notifications. |
| **API-документация** | Swagger / OpenAPI | Проект использует подход API-First, поэтому ручки нужно описывать заранее. Swagger позволяет быстро смотреть запросы и ответы, а также синхронизировать работу frontend и backend. |
| **Основная БД** | PostgreSQL | В проекте много связанных сущностей: пользователи, роли, профпробы, слоты, записи, платежи и результаты. PostgreSQL надёжно хранит структурированные данные и помогает избежать несогласованности, например записи без оплаты или результата без участника. |
| **ORM** | Prisma / TypeORM | Упрощает работу с базой данных: модели пользователей, профпроб, записей, оплат и результатов описываются в коде. Это ускоряет разработку и снижает риск ошибок в SQL-запросах. |
| **Платежи** | ЮKassa / CloudPayments / внешний платёжный провайдер | Профпробы оплачиваются разово: пользователь или родитель платит за конкретное занятие. Платёжный провайдер безопасно обрабатывает оплату, а backend получает только статус платежа и подтверждает запись после успешной оплаты. |
| **Email-уведомления** | SMTP-сервис / SendGrid / UniSender | Нужны для подтверждения записи, уведомлений об оплате и сообщения о готовности результата. Для MVP email достаточно надёжен и проще, чем полноценная система push-уведомлений. |
| **Push-уведомления** | Web Push / Firebase Cloud Messaging | Можно использовать для напоминаний о профпробе и уведомлений о готовности результата. Для MVP push можно оставить как расширение после email. |
| **Дистанционные занятия** | Zoom / Google Meet / Яндекс Телемост | Дистанционные профпробы не требуют собственной видеоплатформы. Достаточно хранить ссылку на встречу и показывать её участнику после успешной записи и оплаты. |
| **Хранилище файлов** | S3-совместимое Object Storage | Может использоваться для материалов профпроб: заданий, изображений, файлов для анализа, шаблонов интерфейсов и вложений. Это удобнее, чем хранить файлы прямо в базе данных. |
| **Кеширование и очереди** | Redis | Может использоваться для временного удержания места на профпробе во время оплаты, кеширования популярных профпроб и очереди уведомлений. Это снижает нагрузку на базу данных и помогает избежать двойной записи на одно место. |
| **Фоновый воркер** | BullMQ / NestJS Queues + Redis | Нужен для задач, которые не должны блокировать основной API: отправка писем, напоминания о занятии, обработка статусов платежей, уведомления о готовности результата. |
| **Авторизация и роли** | JWT + Role-Based Access Control | В системе разные роли: учащийся, родитель, наставник, администратор. RBAC помогает ограничить доступ: например, наставник видит только свои занятия, а участник — только свои результаты. |
| **Контейнеризация** | Docker | Позволяет запускать frontend, backend, базу данных и Redis в одинаковой среде у разработчика и на сервере. Упрощает развёртывание MVP. |
| **CI/CD** | GitHub Actions + Docker | Автоматически проверяет проект при изменениях: запускает тесты, собирает приложение и готовит Docker-образ. Это снижает риск сломать рабочую версию. |
| **Наблюдаемость** | Sentry + базовые метрики | Sentry помогает видеть ошибки frontend и backend после запуска MVP. Базовые метрики позволяют отслеживать записи, оплаты, ошибки API и неуспешные попытки оплаты. |
| **Хостинг** | Yandex Cloud / Selectel / VPS | Для MVP достаточно простого облачного сервера или managed-сервисов для PostgreSQL и Object Storage. Сложный Kubernetes на старте не обязателен. |
