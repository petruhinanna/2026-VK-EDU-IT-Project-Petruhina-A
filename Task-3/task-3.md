# Практическое задание №3. Системный анализ

## 1. DDD — доменные зоны

Приложение разделено на 5 доменных зон. Каждая зона отвечает за отдельную часть продукта и использует свои ключевые термины.

---

### 1.1. Пользователи и роли

**Описание.**  
Зона отвечает за регистрацию, авторизацию и роли пользователей в системе. В IT QUEST есть несколько типов пользователей: учащийся, родитель, наставник и администратор.

**Глоссарий.**

| Термин | Описание |
|---|---|
| Пользователь | Зарегистрированный человек, который имеет доступ к платформе. |
| Учащийся | Основной пользователь, который выбирает профпробу, записывается на неё и получает результат. |
| Родитель | Пользователь, который помогает учащемуся принять решение об участии и может смотреть информацию о профпробе. |
| Наставник | Специалист, который проводит профпробу и заполняет результат по участнику. |
| Администратор | Пользователь, который управляет профпробами, расписанием и пользователями. |
| Личный профиль | Раздел, где пользователь видит свои записи и результаты профпроб. |

---

### 1.2. Каталог профпроб

**Описание.**  
Зона отвечает за список доступных профпроб, IT-направления, описание занятий и информацию о формате прохождения.

**Глоссарий.**

| Термин | Описание |
|---|---|
| Профпроба | Практическое занятие, на котором участник пробует задачи из конкретной IT-профессии. |
| IT-направление | Область IT, например тестирование, frontend-разработка, аналитика данных, UX/UI-дизайн или кибербезопасность. |
| Карточка профпробы | Страница с описанием занятия, датой, временем, форматом и количеством свободных мест. |
| Формат профпробы | Способ прохождения занятия: очно или дистанционно. |
| Длительность | Время проведения профпробы, обычно 90–120 минут. |

---

### 1.3. Запись на профпробу

**Описание.**  
Зона отвечает за выбор слота, проверку свободных мест, создание записи и подтверждение участия.

**Глоссарий.**

| Термин | Описание |
|---|---|
| Запись | Подтверждённое участие пользователя в конкретной профпробе. |
| Слот | Конкретная дата и время проведения профпробы. |
| Свободное место | Доступное место на выбранном занятии. |
| Лимит участников | Максимальное количество участников на одной профпробе. |
| Подтверждение записи | Сообщение о том, что пользователь успешно записан на занятие. |
| Отмена записи | Действие, при котором пользователь отказывается от участия до начала профпробы. |

---

### 1.4. Проведение профпробы

**Описание.**  
Зона отвечает за само занятие: очное или дистанционное прохождение, практическое задание, работу наставника и участие пользователя.

**Глоссарий.**

| Термин | Описание |
|---|---|
| Занятие | Проведение профпробы в выбранное время. |
| Участник | Учащийся, который записался и проходит профпробу. |
| Практическое задание | Мини-задача из реальной IT-профессии. |
| Наставник занятия | Специалист, который объясняет задачу, помогает участникам и даёт обратную связь. |
| Очная профпроба | Занятие, которое проходит в аудитории IT-школы или образовательного центра. |
| Дистанционная профпроба | Занятие, которое проходит онлайн, если участник не может прийти лично. |

---

### 1.5. Результаты профпроб

**Описание.**  
Зона отвечает за внесение результата наставником, хранение итогов и отображение результата пользователю в личном профиле.

**Глоссарий.**

| Термин | Описание |
|---|---|
| Результат профпробы | Итог занятия, который наставник заполняет после прохождения профпробы. |
| Комментарий наставника | Текстовая обратная связь по участнику. |
| Что получилось хорошо | Часть результата, где описываются сильные стороны участника на занятии. |
| Что вызвало трудности | Часть результата, где описываются сложности во время выполнения задания. |
| Общий вывод | Мягкая рекомендация о том, стоит ли дальше изучать выбранное направление. |
| История результатов | Список профпроб, которые участник уже прошёл. |

---

## 2. BDD — критический путь MVP

**Критический путь MVP:**  
Участник выбирает профпробу, записывается на свободное место, проходит занятие и получает результат в личном профиле.

---

**Сценарий 1: Учащийся успешно записался на профпробу и получил результат**


Функция: Запись на профпробу и получение результата

Учащийся авторизован на платформе. В каталоге есть профпроба «Тестирование », и на выбранный слот есть свободные места.

Пользователь открывает карточку профпробы и нажимает кнопку «Записаться». Система проверяет наличие свободных мест, закрепляет место за пользователем и показывает подтверждение записи с датой, временем, форматом и адресом занятия.

После этого учащийся приходит на профпробу или подключается дистанционно, проходит практическое задание, а наставник вносит результат по участнику. Система сохраняет результат, и учащийся может увидеть его в личном профиле.

**Сценарий 2. Отказ при отсутствии свободных мест**

  Функция: Запись на профпробу

Учащийся авторизован на платформе. В каталоге есть профпроба «Frontend », но на выбранный слот уже нет свободных мест.

Пользователь открывает карточку профпробы и нажимает кнопку «Записаться». Система проверяет доступность мест и не создаёт запись, потому что лимит участников уже достигнут.

После этого система показывает сообщение: «Свободных мест на эту профпробу нет» и предлагает выбрать другой слот. Пользователь остаётся без записи на выбранное занятие, но может перейти к другим доступным датам или выбрать другую профпробу.

## 3. Wireframes — ключевые экраны

Грубые макеты «квадратиками» — 4 экрана критического пути MVP:

Каталог профпроб — пользователь выбирает IT-направление.
Карточка профпробы — пользователь смотрит дату, время, формат, место и свободные места.
Подтверждение записи — пользователь видит, что запись прошла успешно.
Результат профпробы — пользователь смотрит итог, который внёс наставник.
