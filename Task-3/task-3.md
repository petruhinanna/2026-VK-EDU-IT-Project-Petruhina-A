# Практическое задание №3. Системный анализ

- Необходимо разделить приложение на 4–5 доменных зон по DDD и для каждой зоны описать глоссарий.
- Выбрать один критический путь MVP и описать его по BDD в формате “Дано — Когда — Тогда”.
- Набросать 2–4 ключевых экрана в формате простых wireframes.
- Спроектировать 1–2 API-контракта в формате JSON: запрос и ответ.



## 1. DDD — доменные зоны

Приложение **IT QUEST** разделено на 5 доменных зон.  
Каждая зона отвечает за отдельную часть продукта и использует свои ключевые термины.

---

### 1.1. Пользователи и роли

**Описание.**  
Зона отвечает за регистрацию, авторизацию, роли пользователей и доступ к личному профилю.

**Глоссарий.**

| Термин | Описание |
|---|---|
| Пользователь | Зарегистрированный человек, который имеет доступ к платформе. |
| Учащийся | Основной пользователь, который выбирает профпробу, записывается на неё, проходит занятие и получает результат. |
| Родитель | Пользователь или плательщик, который помогает учащемуся принять решение и оплачивает участие. |
| Наставник | Специалист, который проводит профпробу и заполняет результат по участнику. |
| Администратор | Пользователь, который управляет профпробами, расписанием, пользователями и контентом. |
| Личный профиль | Раздел, где пользователь видит свои записи, статусы оплат и результаты профпроб. |

---

### 1.2. Каталог профпроб

**Описание.**  
Зона отвечает за список доступных профпроб, IT-направления, описание занятий и формат прохождения.

**Глоссарий.**

| Термин | Описание |
|---|---|
| Профпроба | Практическое занятие, на котором участник пробует задачи из конкретной IT-профессии. |
| IT-направление | Область IT: тестирование, frontend-разработка, аналитика данных, UX/UI-дизайн или кибербезопасность. |
| Карточка профпробы | Страница с описанием занятия, датой, временем, форматом, ценой и количеством свободных мест. |
| Формат профпробы | Способ прохождения занятия: очно или дистанционно. |
| Длительность | Время проведения профпробы, обычно 90–120 минут. |

---

### 1.3. Запись и оплата профпробы

**Описание.**  
Зона отвечает за выбор слота, временную бронь места, оплату, подтверждение записи и отмену участия.

**Глоссарий.**

| Термин | Описание |
|---|---|
| Запись | Подтверждённое участие пользователя в конкретной профпробе. |
| Слот | Конкретная дата и время проведения профпробы. |
| Свободное место | Доступное место на выбранном занятии. |
| Лимит участников | Максимальное количество участников на одной профпробе. |
| Временная бронь | Удержание места на ограниченное время, пока пользователь переходит к оплате. |
| Оплата | Денежная операция, после которой запись может быть подтверждена. |
| Статус записи | Состояние записи: забронировано, ожидает оплаты, оплачено, подтверждено, отменено. |
| Подтверждение записи | Сообщение о том, что пользователь успешно записан на занятие. |
| Отмена записи | Действие, при котором пользователь отказывается от участия до начала профпробы. |

---

### 1.4. Проведение профпробы

**Описание.**  
Зона отвечает за само занятие: очное или дистанционное прохождение, практическое задание, работу наставника и участие пользователя.

**Глоссарий.**

| Термин | Описание |
|---|---|
| Занятие | Проведение профпробы в выбранное время. |
| Участник | Учащийся, который записался и проходит профпробу. |
| Практическое задание | Мини-задача из реальной IT-профессии. |
| Наставник занятия | Специалист, который объясняет задачу, помогает участникам и даёт обратную связь. |
| Очная профпроба | Занятие, которое проходит в аудитории IT-школы или образовательного центра. |
| Дистанционная профпроба | Занятие, которое проходит онлайн, если участник не может прийти лично. |

---

### 1.5. Результаты профпроб

**Описание.**  
Зона отвечает за внесение результата наставником, хранение итогов и отображение результата пользователю в личном профиле.

**Глоссарий.**

| Термин | Описание |
|---|---|
| Результат профпробы | Итог занятия, который наставник заполняет после прохождения профпробы. |
| Комментарий наставника | Текстовая обратная связь по участнику. |
| Что получилось хорошо | Часть результата, где описываются сильные стороны участника на занятии. |
| Что вызвало трудности | Часть результата, где описываются сложности во время выполнения задания. |
| Общий вывод | Мягкая рекомендация о том, стоит ли дальше изучать выбранное направление. |
| История результатов | Список профпроб, которые участник уже прошёл. |

---

## 2. BDD — критический путь MVP

**Критический путь MVP:**  
Участник выбирает профпробу, бронирует место, оплачивает участие, получает подтверждение записи, проходит занятие и получает результат в личном профиле.

---

### Сценарий 1. Успешная запись на профпробу и получение результата

**Функция:** запись, оплата и получение результата профпробы.

**Дано:** учащийся авторизован на платформе.  
**И:** в каталоге есть профпроба “Тестирование”.  
**И:** на выбранный слот есть свободные места.  
**И:** стоимость профпробы составляет 990 рублей.

**Когда:** учащийся открывает карточку профпробы.  
**И:** выбирает доступный слот.  
**И:** нажимает кнопку “Записаться”.  
**И:** система временно бронирует место.  
**И:** пользователь оплачивает профпробу.  
**И:** платёжный сервис возвращает успешный статус оплаты.

**Тогда:** система подтверждает запись.  
**И:** место закрепляется за пользователем.  
**И:** пользователь видит подтверждение с датой, временем, форматом и адресом или ссылкой занятия.  
**И:** запись сохраняется в личном профиле.

**Когда:** учащийся проходит профпробу.  
**И:** наставник вносит результат по участнику.

**Тогда:** система сохраняет результат.  
**И:** учащийся может увидеть результат в личном профиле.

---

### Сценарий 2. Отказ при отсутствии свободных мест

**Функция:** запись на профпробу.

**Дано:** учащийся авторизован на платформе.  
**И:** в каталоге есть профпроба “Frontend-разработка”.  
**И:** на выбранный слот нет свободных мест.

**Когда:** пользователь открывает карточку профпробы.  
**И:** нажимает кнопку “Записаться”.

**Тогда:** система не создаёт запись.  
**И:** система показывает сообщение: “Свободных мест на эту профпробу нет”.  
**И:** система предлагает выбрать другой слот или другую профпробу.

## 4. API-First — JSON-контракты

API — это способ общения frontend и backend.

Например: пользователь нажимает кнопку **“Записаться”** на сайте.  
Frontend отправляет запрос на backend.  
Backend проверяет данные и возвращает ответ: запись создана или мест нет.

---

### Ручка 1. `POST /api/bookings` — запись на профпробу

**Описание:**  
Пользователь выбирает профпробу и слот. Система проверяет свободные места и создаёт запись.

**Запрос:**

```json
{
  "user_id": "user_1001",
  "trial_id": "trial_101",
  "slot_id": "slot_501"
}
```

**Ответ 201 — запись успешно создана:**

```json
{
  "booking_id": "booking_3001",
  "status": "confirmed",
  "trial_title": "Профпроба: Тестирование",
  "format": "offline",
  "date": "2026-05-20",
  "time": "15:00",
  "place": "Москва, образовательный центр IT QUEST, аудитория 204",
  "message": "Вы успешно записаны на профпробу."
}
```

**Ответ 400 — свободных мест нет:**

```json
{
  "error": "NO_FREE_PLACES",
  "message": "Свободных мест на эту профпробу нет. Выберите другой слот."
}
```

---

### Ручка 2. `POST /api/results` — сохранение результата профпробы

**Описание:**  
После занятия наставник заполняет результат профпробы. Система сохраняет результат в личном профиле учащегося.

**Запрос:**

```json
{
  "booking_id": "booking_3001",
  "student_id": "user_1001",
  "mentor_id": "user_2001",
  "strong_points": "Учащийся быстро понял логику поиска ошибок.",
  "difficulties": "Было сложно определить критичность ошибки.",
  "conclusion": "Направление тестирования стоит попробовать дальше."
}
```

**Ответ 201 — результат сохранён:**

```json
{
  "result_id": "result_8001",
  "status": "saved",
  "message": "Результат профпробы сохранён и доступен учащемуся в личном профиле."
}
```

**Ответ 403 — нет доступа:**

```json
{
  "error": "ACCESS_DENIED",
  "message": "Наставник может внести результат только для участника своей профпробы."
}
```
